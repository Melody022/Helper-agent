### 消息路由链（核心）

```
① 身份（必须登录）
② 系统命令（/reset）
③ 跨域判定（命中 ≥2 个不同 Agent 就走综合子图）
   然后：关键词扫描 → 命中且与粘性一致就沿用、不一致就切
④ 指代消解（仅"没粘性 + 关键词也没命中"才走）
⑤ 三层意图分类
⑥ Agent 匹配（注册表 + 角色权限 + 优先级）
⑦ 审计
```

**关键顺序约束**：跨域判定必须在单意图定案**之前**。因为所有高权重关键词都是 0.9 分，
两个高权重意图必然同分，单意图那条路要求"严格高于第二名"，对跨域输入天然判不出来。

## 四、已定的设计决策（别再推翻）

| 决策 | 理由 |
|---|---|
| **必须登录才能用**，不做游客 | 能查到平台侧数据、能代用户发布，匿名没法做权限控制 |
| **系统命令只留 `/reset`** | `/help` 对用户没用（"你能做什么"就是闲聊意图） |
| **粘性靠关键词扫描兜底，不是无条件短路** | 先短路就永远发现不了用户换话题 |
| **兜底 Agent 不挂任何工具** | 它一旦能查数据，会在路由出错时给出"看似可信其实串了领域"的答案，掩盖真问题 |
| **发布是确定性工作流，模型只负责抽字段** | 发布是写操作，模型抽错了会被校验拦下重填，不会写半截数据 |
| **只读 Mapper 与写入 Mapper 分包** | 查询是运行时拼条件的（易脏数据），写入只在确定性路径上，混在一起就失去隔离意义 |
| **提示词放 .md 文件，不放数据库** | 数据库方案会丢掉代码评审、git 回滚、环境一致性；而提示词里有防幻觉护栏，被随手改掉会出事 |
| **数据来源只认 `biz_base_region`** | 库里的 `region`/`ls_province` 等是干扰项 |

## 五、踩过的坑

**完整清单见 `docs/踩坑记录与量化数据.md`（28 条）**，每条都是「现象 → 怎么发现的 → 根因 → 怎么修」。

### 最值得在面试里讲的五个

1. **静默降级**（第 11 条）：模型调用统一 8 秒超时，而本地模型冷启动要十几秒。
   两层双双超时 → 这句话被判成 UNKNOWN、**静默降级到兜底**。用户只觉得"答得敷衍"。
   *教训：静默失败比报错危险；超时要按层设置；可观测性要先做。*

2. **跨域被单 Agent 吃掉**（第 15 条）：匹配规则先比"能力交集个数"，
   跨域意图声明了 5 个能力、RentalAgent 交集 3 个 → 整条交给它。
   **而 `ai_agent.priority` 配了也没用——先比交集，平手才看优先级。**
   *教训：配置项写了不等于会生效。*

3. **自评误杀**（第 25 条）：提示词写"出现资料中没有的数字就判否"，
   实际效果是**暗示模型"看到数字就判否"**，把正确答案误杀了。
   *教训：否定句会把模型注意力引到那个东西上。*

4. **MyBatis-Plus 的 `updateById` 跳过 null 字段**（第 26/27 条类）：
   清理令牌时 `setXxx(null)` + `updateById` 根本清不掉，令牌一直留在库里可被重放。
   同类坑还踩过一次"逻辑删除导致测试数据越积越多"。
   *教训：修完一个坑要顺带搜一遍同类代码。*

5. **证据闸阈值是拍的**（见第六节，**当前最重要的未解决问题**）。

## 六、已知问题（接手优先处理）

### 🔴 1. 证据闸阈值形同虚设（最重要）

**现象**：知识库有内容之后，一个完全不相关的问题（"平台的火箭发射服务怎么预约"）
向量相关度能拿到 **0.7655**，远超 `min-retrieval-score` 默认的 0.6，**证据闸直接放行**。
真正拦住它的是第二道自评——而自评时灵时不灵。

**影响**：不该答的问题有一半概率被答出来。

**修法**（已记入 `docs/待办-评测与量化.md`）：标一批「问题→应该命中哪条规则」的对应关系，
画"阈值 vs 误拦率/漏放率"曲线重新选点。**不要再拍一个数字。**

对应测试 `M6KnowledgeTest.refusesAndRecordsWhenKnowledgeMissing` 已用 `@Disabled` 标记并写明原因。

### 🟡 2. 自评（用 7B 小模型）判定不稳定

同一个问题、同一份资料，本地 qwen2.5:7b 时而判通过、时而判不通过。

**可选修法**：① 改用主模型做自评（更准但更贵）；② 判"否"时重问一次取多数；
③ 判不出来时按通过处理（当前就是这个策略，所以漏放）。

**注意**：因为自评不稳定，**不要把测试断言建在"最终答没答上来"上**——
`M6KnowledgeTest` 里已经改成只断言检索与证据闸（确定性部分），
把这条经验写在了测试注释里。

### 🟡 3. 测试数据会污染检索结果

ES 的删除是近实时的，上一轮测试的 `[测试]` 文档可能还没清掉，挤掉正确答案。
现有测试里靠"召回取大一点 + 过滤测试数据"绕过。

## 九、项目里的"雷区"（别踩）

| 雷区 | 说明 |
|---|---|
| `knowledge_base` ES 索引 | 上一个项目的数据，**不要动、不要覆盖** |
| 全局逻辑删除配置 | 刻意**没配** `logic-delete-field`：`jxb_chuzu` 活动行的 `del_flag` 是空串/NULL 而非 '0'，配了会把 14 条在租记录全过滤掉 |
| `mapper.jxj` 包 | 有只读护栏，写入会被拦。写入要用 `mapper.publish` |
| `cms_article.desc` | MySQL 保留字，实体上加了反引号转义 |
| Jackson | 业务代码统一用 Jackson 3（`tools.jackson.*`）。ES 客户端那处的 Jackson 2 是它自带的，**不要扩散** |
| `taskkill /IM java.exe` | 会把 ES 一起杀掉（ES 也是 java 进程）。**按 PID 杀** |
| 测试数据清理 | 必须**物理删除**（`JdbcTemplate`），`deleteById` 走逻辑删除清不干净 |
