### 消息路由链（核心）

```
① 身份（必须登录）
② 系统命令（/reset）
③ 跨域判定（命中 ≥2 个不同 Agent 就走综合子图）
   然后：关键词扫描 → 命中且与粘性一致就沿用、不一致就切
   关键词没命中 + 有粘性 + **含指代词** → 沿用粘性（"那这个呢"脱离上文没法理解，几乎必然是追问）
   关键词没命中 + **不含指代词** → 不复用粘性，走第 ④⑤ 步连同上文重新分类
④ 指代消解（只有真要叫模型时才做）
⑤ 三层意图分类
⑥ Agent 匹配（注册表 + 角色权限 + 优先级）
⑦ 审计
```

**关键顺序约束**：跨域判定必须在单意图定案**之前**。因为所有高权重关键词都是 0.9 分，
两个高权重意图必然同分，单意图那条路要求"严格高于第二名"，对跨域输入天然判不出来。

## 四、已定的设计决策（别再推翻）

| 决策 | 理由 |
|---|---|
| **必须登录才能用**，不做游客 | 能查到平台侧数据、能代用户发布，匿名没法做权限控制 |
| **系统命令只留 `/reset`** | `/help` 对用户没用（"你能做什么"就是闲聊意图） |
| **粘性只在"含指代词"时才沿用** | 判据只有一条：关键词没命中 **且** 含指代词。**没有字数阈值**——曾经有过，删掉了，理由见踩坑第 48 条：中文一句话信息密度高，"挖掘机驾驶室有什么要求吗"正好 12 个字却是一句完整的问题。**不要再用形态判据去猜语义** |
| **兜底 Agent 不挂任何工具** | 它一旦能查数据，会在路由出错时给出"看似可信其实串了领域"的答案，掩盖真问题 |
| **发布是确定性工作流，模型只负责抽字段** | 发布是写操作，模型抽错了会被校验拦下重填，不会写半截数据 |
| **只读 Mapper 与写入 Mapper 分包** | 查询是运行时拼条件的（易脏数据），写入只在确定性路径上，混在一起就失去隔离意义 |
| **提示词放 .md 文件，不放数据库** | 数据库方案会丢掉代码评审、git 回滚、环境一致性；而提示词里有防幻觉护栏，被随手改掉会出事 |
| **数据来源只认 `biz_base_region`** | 库里的 `region`/`ls_province` 等是干扰项 |

## 五、踩过的坑

**完整清单见 `docs/踩坑记录与量化数据.md`（50 条）**，每条都是「现象 → 怎么发现的 → 根因 → 怎么修」。

### 最值得在面试里讲的五个

1. **静默降级**（第 11 条）：模型调用统一 8 秒超时，而本地模型冷启动要十几秒。
   两层双双超时 → 这句话被判成 UNKNOWN、**静默降级到兜底**。用户只觉得"答得敷衍"。
   *教训：静默失败比报错危险；超时要按层设置；可观测性要先做。*

2. **跨域被单 Agent 吃掉**（第 15 条）：匹配规则先比"能力交集个数"，
   跨域意图声明了 5 个能力、RentalAgent 交集 3 个 → 整条交给它。
   **而 `ai_agent.priority` 配了也没用——先比交集，平手才看优先级。**
   *教训：配置项写了不等于会生效。*

3. **自评误杀**（第 25 条）：提示词写"出现资料中没有的数字就判否"，
   实际效果是**暗示模型"看到数字就判否"**，把正确答案误杀了。
   *教训：否定句会把模型注意力引到那个东西上。*

4. **MyBatis-Plus 的 `updateById` 跳过 null 字段**（第 26/27 条类）：
   清理令牌时 `setXxx(null)` + `updateById` 根本清不掉，令牌一直留在库里可被重放。
   同类坑还踩过一次"逻辑删除导致测试数据越积越多"。
   *教训：修完一个坑要顺带搜一遍同类代码。*

5. **证据闸阈值是拍的**（见第六节，**当前最重要的未解决问题**）。

## 六、已知问题

### ✅ 1. 证据闸阈值形同虚设（**2026-09-12 已修复**）

**当时的现象**：知识库有内容之后，一个完全不相关的问题（"平台的火箭发射服务怎么预约"）
向量相关度能拿到 **0.7655**，远超 `min-retrieval-score` 默认的 0.6，**证据闸直接放行**。
真正拦住它的是第二道自评——而自评时灵时不灵。不该答的问题有一半概率被答出来。

**修的时候没有"再拍一个数字"**。标了 34 条样本画曲线，发现**向量相似度这个判据本身
就没有可用分界点**——有答案的 0.697~0.928 和无答案的 0.631~0.829 几乎完全重叠，
阈值取 0.6 时漏放 100%，取到 0.83 才不漏放但那时 54% 能答的也被拒了。

**根因**：双塔向量相似度是"各自算好再比"，对"资料里到底有没有回答这个问题"不敏感，
**适合排序、不适合判定**。

**修法**：加**精排（交叉编码器）**做主判据，链路变成
`混合召回收窄候选 → 精排打分 → 证据闸按精排分判定`，阈值 0.19。
**效果**：漏放率 100% → 0%，误拦率 0% → 13%（刻意偏保守：误拦转人工，漏放是给出编造的答案）。

> 还有一个值钱的细节：喂给精排的必须是**「标题 + 正文」**而不是只有正文——
> 知识库标题是问句形态、正文是陈述式的，只喂正文时"押金怎么退"只能拿 0.18，
> 加上标题能到 0.79，**误拦率 29% → 13%**。详见踩坑记录第 29 条。

- 实现：`rag/RerankScorer.java`（DashScope `gte-rerank-v2`）、`rag/EvidenceGate.java`
- 校准脚本：`RetrievalEvalTest`（含 Recall@K 三路对比），跑法见第二节
- 完整记录：`docs/踩坑记录与量化数据.md` 第 29 条
- 对应测试 `refusesAndRecordsWhenKnowledgeMissing` 已从 `@Disabled` 恢复，现稳定通过

**还可以更好**：13% 的误拦率说明**瓶颈已经不是闸、而是召回**——剩下被误拦的基本都是
对的资料压根没进候选集（比如"你们抽几个点"连 top-5 都没进），精排再准也救不回来。
下一步试更强的中文 embedding 模型，或做 Query 扩写。

### ⚠️ 5. 主模型 `mimo-v2.5` 服务端故障时的处置（2026-09-12 遇到过）

**现象**：所有需要生成回答的问题都答不上来，日志里是

```
ModelCaller: 模型调用失败或超时（60000ms）：
  com.openai.errors.InternalServerException: 500: Internal Server Error
→ 知识线未作答：生成回答失败
```

用户侧看到的是"这个问题我答不上来，建议转人工"——**和"知识库没资料"长得一模一样**，
很容易误判成检索或证据闸的问题。

**怎么区分是不是模型挂了**（30 秒就能确认）：

```bash
# 同一把 key，先看认证和端点是否正常
curl -s -H "Authorization: Bearer $MIMO_API_KEY" "$MIMO_BASE_URL/models" | head -c 200
# 再直接打一次对话
```

**当时的判定**：`/models` 返回 200（key 有效）、`mimo-v2.5` 每次都 500 且 0.2 秒快速失败、
**同一把 key 下 `mimo-v2.5-pro` 正常**。→ 不是额度、不是 key、不是我们的代码，
**是那一个模型的推理后端挂了**。（额度问题通常是 429 或带说明的 403，不会是 500；
而且额度是账户级的，不会只挂一个模型。）

**处置**：`.env` 里改一个变量就行，不用动代码——

```
MIMO_MODEL=mimo-v2.5-pro
```

改完重启应用。**注意 `-pro` 是推理型，慢很多**（实测单轮 17~38 秒），
基础模型恢复后建议换回去（拿 `/models` + 一次真实对话确认）。

**要不要做自动降级？** 目前没有：主模型挂了就是生成失败 → 记飞轮 → 转人工，
路由层会降级（小模型/关键词），但生成层没有备选。要不要加"主模型失败自动切备用模型"
取决于成本考虑——**自动重试/切换可能重复计费**（和项目"不做自动重试"的决策同源）。
至少现在**换了模型名要重启**这一点是明确的。

## 九、项目里的"雷区"（别踩）

| 雷区 | 说明 |
|---|---|
| `knowledge_base` ES 索引 | 上一个项目的数据，**不要动、不要覆盖** |
| 全局逻辑删除配置 | 刻意**没配** `logic-delete-field`：`jxb_chuzu` 活动行的 `del_flag` 是空串/NULL 而非 '0'，配了会把 14 条在租记录全过滤掉 |
| `mapper.jxj` 包 | 有只读护栏，写入会被拦。写入要用 `mapper.publish` |
| `cms_article.desc` | MySQL 保留字，实体上加了反引号转义 |
| Jackson | 业务代码统一用 Jackson 3（`tools.jackson.*`）。ES 客户端那处的 Jackson 2 是它自带的，**不要扩散** |
| `taskkill /IM java.exe` | 会把 ES、IDEA 一起杀掉（都是 java 进程）。**按 PID 杀** |
| **杀"我起的应用"时别误杀 IDEA 的** | 两者命令行**都含 `jixiejia`**（IDEA 启动的也是这个应用的类）。<br>判据看这三处：**有没有 `plexus-classworlds` 父进程**（`mvn spring-boot:run` 才有）、<br>JDK 是 17（我起）还是 21（IDEA 起）、命令行有没有 `-agentlib:jdwp` / `JetBrains\...debugger-agent`（IDEA 注入的）。<br>**拿不准就先打印命令行看一眼，宁可少杀不要误杀** |
| 测试数据清理 | 必须**物理删除**（`JdbcTemplate`），`deleteById` 走逻辑删除清不干净 |
| **应用运行时跑 `mvn`** | `mvn compile/test` 会**清空并重建 `target/classes`**，运行中的 JVM 正好去加载被删的类就报 `ClassNotFoundException`。**看着像"代码少了类"，其实只是那一瞬间文件不在**。要么别在应用跑着时构建，要么构建完重启应用 |
