## 四、最近一轮做了什么

**这一轮：意图识别——扩评估集 + 修"发布意图认不出来"**

1. **需求是用户用出来的**："我想出租一台洋马60"被答成"平台上暂时没有洋马60的出租信息"——
   **把发布判成了查询**。这是同一个结构问题的**第三次**发作（第 19、20 条 + 这次）。
2. **先补量尺再改代码**（第 51 条）—— 旧评估集 26 条里"发布"只有 1 条，且恰好是
   词表专门写过的"帮我发布一台出租"，**改坏了也看不出来**。
   扩到 **63 条**并加"发布 vs 查询""跨域 vs 不该跨域"两组对照后，
   **同一套代码**的基线从 96.2% 掉到 **87.3%**——不是变差了，是原来的尺子量不出来。
3. **改法**：`发布` 从定案词里拿掉（太泛）＋ 新增"意愿词 × 发布动作词同现"的判断 ＋
   **命中后只让路、不定案，并把"这是发布意愿"当提示喂给模型**。
4. **关键取舍**：**提示是建议（模型能推翻），定案是结论（错了就是错的）**。
   同一条判据当提示用是安全的，当判据用是危险的。实测"只让路不给提示"照样错
   （7B 小模型缺"主体是机主"的证据）。
5. **顺带修了跨域漏判**（第 52 条）—— 查下来发现：**执行层一直是好的**
   （`CompositeGraph` 的并行扇出 + 汇总），**模型也判得出来**，问题是
   **关键词层抢答、模型根本没轮到**。而过得那 3 条跨域样本，靠的是
   "两个高权重词同分→下沉给模型"这个**副作用**，不是跨域判定本身。
   修法：别的**业务域**也在说话时不许抢答。跨域 3/4 → **4/4**。
6. **量出来的完整归因**（每版都跑同一套 63 条）：87.3% → 92.1%（让路）→
   **90.5%（描述改太长，退了，已回退）** → 92.1%（加提示）→ 93.7%（回退冗长描述）
   → 95.2%（修跨域抢答）→ **96.8%（删掉与"求租"重复的"需求"意图）**。
7. **删掉"需求"这个独立功能**（第 53 条，用户拍板）——查下来发现项目**三处描述互相矛盾**：
   `QiuzuQueryTool` 说"要用机器的人正在找机器"、`ToolCapability` 说"机主找活"、
   `Intent` 说"用户是机主…"——**两个方向**，而数据库站在工具那边。
   根因是平台把"求租"和"用机需求"建成了两张表，代码里就有两个意图两个工具，
   而**业务上是同一件事**。删意图 + 合并工具（`search_qiuzu` 一次查两张表）后
   **准确率 95.2% → 96.8%，PUBLISH_CHUZU 7/7，所有"需求"相关错判消失**。

> ⚠️ **简历上的意图准确率要用 96.8%（61/63）**，不是原来的 96.2%（25/26）。
> 旧数字样本太少、且给错误行为背了书。完整的故事线在 `简历与面试-主文档.md` 第四节亮点 4/5。

**上一轮：修路由粘性 + 修一个"兜底不兜底"的解析 bug**

1. **粘性兜底只认指代词** —— 用户报"每次都是粘性兜底、每次都误判"，日志里
   "挖掘机驾驶室有什么要求吗"（**正好 12 个字**）被粘在了 RentalAgent 上。
   根因是判据里有一条"字数 ≤ 12 就算追问"——**那是在猜**（第 48 条）。
   删掉字数判据和配置项，只留"含指代词"（语义判据）。代价：不含指代词的短句多跑一次**本地**模型。
2. **"兜底"其实不兜底**（第 49 条）—— `splitPages` 的两条兜底分支返回
   `List.of(...)`（**不可变**），而 `applyOcr` 要 `set()` 写回 OCR 结果 →
   `UnsupportedOperationException` → **整篇 OCR 文字全丢**。**传一张单页扫描的 PDF 必中。**
3. **进度日志分子分母不同量纲**（第 50 条）—— 用户问"为什么 PDF 一共 21 页，进度表能切 30 多"，
   查下来那份文档**实际 31 页**，21 是"需要 OCR 的页数"，被当日母用了。

**更早一轮：引用角标 + 原件回溯**（让答案里的 `[1]` 点得下去）

1. **需求是用户"用"出来的** —— 我们已经能说"依据来自国标第 10 页"，
   用户一句"**我想要前端回溯原始的 PDF 不行吗**"才暴露出：说法和入口是两回事。
2. **原件落盘** —— 上传时先留原件（文件名用**内容指纹**，重传同一份天然去重），
   文档表加 `file_name/file_path/preview_path/file_size`。
3. **"转 PDF"不是默认动作，是给 Office 补的例外** —— PDF/图片/txt/csv/md
   **一律原样返回原件**，只有 docx/xlsx/pptx 浏览器渲染不了才转一份预览件。
4. **角标** —— 提示词让模型标 `[1]`，服务端 `CitationSanitizer` 归一化写法，
   前端**先转义再替换**做成可点角标。
5. **点开跳原件** —— PDF.js 单页渲染，直接停在第 N 页；原件用 fetch 带令牌取字节
   （不暴露可另存/转发的直链）。
6. **五个坑**（记录 43–47 条）：扩展名里的路径穿越、形同虚设的转换超时、
   同一条判据写两处必然漂移、**删文档不删原件**（端到端验证撞出来的）、
   指纹去重只覆盖"重传同一份"。

> **边界照实说**：角标只保证**编号合法**，不保证**标得对**（`[3]` 可能其实是 `[1]` 的内容）——
> 那要靠下一轮的 NLI 逐句校验。也**不做命中句高亮**：那份国标是全扫描件、没有文字层。

**更早一轮：证据闸 + 切片结构元数据**

1. **证据闸换判据** —— 标 34 条样本画曲线，发现向量相似度**根本没有可用分界点**（两类完全重叠），**原阈值 0.6 实测漏放率 100%**。换成精排（交叉编码器）后 **100% → 0%**。
   细节：喂精排必须用**「标题+正文」**（标题是问句形态），误拦率 29% → 13%。
2. **召回放宽 + 精排收紧** —— 表格摘要在**向量路排第 2**，却因只走单路被 RRF 累加挤出 top-5，**精排从头到尾没见过它**。改成「召回 20 → 精排 → 取前 5」。
3. **切片结构元数据** —— 按「页 × 章节」拆段、目录剔除、同章节回填、响应带 `sources`。
4. **修了两个"静默失效"bug** —— 会话粘性把完整新问题当追问吃掉；`expandTables` 换构造参数丢元数据。

## 五、核心设计原则（要背）

**① 向量化的是「入口」，不向量化的是「本体」——但本体必须存**
「不向量化」≠「不存」。本体（表格 markdown、父块全文）一律**结构化存库**，靠 `tableId` / `section_path` 取回。

**② 父子块 和 表格，是同一个模式的两次应用**

```
        检索入口（向量化）      本体（不向量化，取回来用）
第一处：  子块                  父块
第二处：  表格摘要              表格本体
```
因为**检索要短而准（长了向量表征就糊），生成要全而完整（缺表头就答错）**。

**③ 融合排序 ≠ 相关性排序** —— RRF 的 `1/(60+名次)` 是累加的，天生偏爱"两路都靠前"，会低估"只在单路极端靠前"的。**融合管"别漏"，精排管"挑准"，不能合成一步。**

**④ 双塔适合排序、不适合判定** —— 向量相似度是"各自算好再比"，对"资料到底有没有回答这个问题"不敏感。

**⑤ 判据选错比阈值调错严重** —— 画曲线的价值是能看出"**选不出来**"。

| **杀进程只按 PID** | `taskkill /F /IM java.exe` 会连 ES 和 IDEA 一起杀（踩坑第 28 条） |
| **我起的应用用完自己杀** | 否则占着 8082，用户 IDEA 起不来 |
| **别在应用运行时跑 `mvn`** | 会清空重建 `target/classes` → `ClassNotFoundException`（第 40 条） |
| **`.env` 的初始密码改了不生效** | 只在"一个 ADMIN 都没有"时建号；改用 `POST /api/auth/password` |
| **测试数据物理删** | `deleteById` 走逻辑删除清不干净 |
| **改 PATH 后重开终端** | 已开着的 shell 拿不到新值 |
| **导中文 SQL 加 `--default-character-set=utf8mb4`** | 否则按 GBK 读，注释写坏 |
| **跑完测试索引数不应变** | 变了说明清理漏了，会污染检索 |
