## 一、主流程图

> **读法**：①~⑦ 全是**判定**，任何一步"提前定案"都不继续往下判，
> 统一产出决策汇到 **⑧ 分派**；⑧ 之后才分岔成四条执行路。
> **⑧ 是整个图唯一的汇聚点**——代码里 identity / command / scan / known / classify / match
> 六个节点的出口，指向的都是它。

## 二、为什么知识线不做成 Agent

这是整个项目里最值得讲的一个设计判断。两张图对比：

```mermaid
%%{init: {'theme':'base','themeVariables':{'primaryColor':'#ffffff','primaryTextColor':'#1f2328','primaryBorderColor':'#d0d7de','lineColor':'#8b949e','secondaryColor':'#ffffff','tertiaryColor':'#ffffff','textColor':'#1f2328','fontSize':'14px'}}}%%
flowchart LR
    subgraph BAD["如果知识线做成 ReAct Agent"]
        direction TB
        B1["模型拿到问题<br/>「押金怎么退」"] --> B2{"要不要调检索工具？"}
        B2 -->|"模型想：<br/>这个我训练数据里见过"| B3["不查资料<br/>直接凭印象答"]
        B2 -->|"决定查"| B4["检索 → 精排 → 证据闸"]
        B3 --> B5["❌ 编出一条平台规则<br/>用户拿到自信满满但错误的答案"]
        B4 --> B6["✅ 正确答案"]
    end

    subgraph GOOD["实际：知识线是代码写死的流水线"]
        direction TB
        G1["用户问题"] --> G2["代码强制：先召回"]
        G2 --> G3["再精排"]
        G3 --> G4["再过证据闸"]
        G4 -->|"资料不够"| G5["✅ 直接回兜底话术<br/>模型压根没机会开口"]
        G4 -->|"资料够"| G6["✅ 生成答案"]
    end

    style BAD fill:#ffffff,stroke:#d0d7de,color:#1f2328
    style GOOD fill:#ffffff,stroke:#d0d7de,color:#1f2328
```

**判据不是"这条线上有没有调模型"，而是"下一步由谁决定"。**

| | 知识线（工作流） | 如果做成 ReAct Agent |
|---|---|---|
| 能跳过检索吗 | 不能，顺序写死 | **能** |
| 能绕过证据闸吗 | 不能，闸在生成**之前** | **能** |
| 会编平台规则吗 | 不会 | **可能** |

```mermaid
%%{init: {'theme':'base','themeVariables':{'primaryColor':'#ffffff','primaryTextColor':'#1f2328','primaryBorderColor':'#d0d7de','lineColor':'#8b949e','secondaryColor':'#ffffff','tertiaryColor':'#ffffff','textColor':'#1f2328','fontSize':'14px'}}}%%
flowchart TD
    HTTP["HTTP 请求"] --> CS["对话服务 ChatService"]
    CS --> RG["<b>路由状态图 RoutingGraph</b><br/>11 节点 / 5 条件边"]

    RG -->|"知识类"| KL["知识线<br/>（不是图，是一条 Java 链）"]
    RG -->|"跨域"| CG["跨域综合图 CompositeGraph<br/>并行扇出 + 汇总"]
    RG -->|"单域"| RA["ReAct 助手 ×4<br/>库预置 ReactAgent"]

    CG -->|"每个域节点内部调用"| RA

    PG["发布图 PublishGraph<br/>4 节点 + interrupt 挂起点<br/>+ MySQL 检查点"]
    PA["发布助手 PublishAgent"] -.->|"独立一条线<br/>不在上面任何图里"| PG

    style RG fill:#fafbfc,stroke:#b9c2cc,stroke-width:2px,color:#1f2328
    style PG fill:#ffffff,stroke:#d0d7de,color:#1f2328
```

**"谁决定走向"总结**（这是项目的设计主线）：

| 图 | 谁决定下一步 | 用到的 LangGraph 能力 |
|---|---|---|
| `RoutingGraph` | **代码** | 条件边 ×5、dispatch 汇聚、`recursionLimit(20)` |
| `CompositeGraph` | **代码**（决定扇出） | 隐式并行节点、appender 通道、扇入 |
| `ReactAgent` ×4 | **模型** | 库预置 ReAct 循环、工具调用 |
| `PublishGraph` | **代码** | **interrupt 挂起 + checkpointer** |

## 四、发布：另一条独立的线（human-in-the-loop）

```mermaid
%%{init: {'theme':'base','themeVariables':{'primaryColor':'#ffffff','primaryTextColor':'#1f2328','primaryBorderColor':'#d0d7de','lineColor':'#8b949e','secondaryColor':'#ffffff','tertiaryColor':'#ffffff','textColor':'#1f2328','fontSize':'14px'}}}%%
flowchart TD
    U(["用户：帮我发布一台出租"]) --> H

    H["handle<br/>抽字段 + 校验"]
    H -->|"字段没齐"| ASK["追问缺什么<br/>（模型只负责抽字段）"]
    ASK --> E1(["⏹ 结束（这一轮到此为止）"])

    H -->|"字段齐了"| SUM["给确认摘要 + 一次性验证码"]
    SUM --> INT{{"☆ interrupt 挂起 ☆<br/>图停在这里等人<br/>状态写进 ai_graph_checkpoint<br/>⚠️ 进程重启也不丢"}}

    INT -->|"用户下一轮回复"| BR{"用户说了什么？"}
    BR -->|"取消"| CN["作废草稿"]
    BR -->|"补充 / 修改"| H
    BR -->|"确认发布"| W["校验验证码<br/>（有效期 + 是否用过）"]
    W -->|"验证码不对"| WARN["提示核对"]
    W -->|"通过"| WRITE["落库，进入待审核"]
    CN --> E2(["⏹ 结束"])
    WARN --> E2
    WRITE --> E2

    style INT fill:#fafbfc,stroke:#b9c2cc,stroke-width:2px,color:#1f2328
```

**为什么这里必须用 checkpointer**：图挂起后，下一轮请求得**从挂起点恢复**——
"挂在哪"必须有地方存。库里只自带 `MemorySaver`（重启就没，和项目原则冲突）
和 `FileSystemSaver`（写本地磁盘），所以自己实现了一个 `MysqlCheckpointSaver`。

```mermaid
%%{init: {'theme':'base','themeVariables':{'primaryColor':'#ffffff','primaryTextColor':'#1f2328','primaryBorderColor':'#d0d7de','lineColor':'#8b949e','secondaryColor':'#ffffff','tertiaryColor':'#ffffff','textColor':'#1f2328','fontSize':'14px'}}}%%

        W1["审计一条 → ai_audit_log<br/>（在 ⑧ 之前就写了）"]
        W2["会话粘性 → Redis ai:sticky:*<br/>（命中助手时）"]
        W3["用户消息 + 助手回复 → ai_message<br/>（在图之后写）"]
        W4["图检查点 → ai_graph_checkpoint<br/>（只有发布图挂起时）"]
        W5["飞轮候选 → ai_flywheel_candidate<br/>（意图认不出 / 知识线拒答时）"]
    end
```

| 存储 | 存什么 | 谁在用 |
|---|---|---|
| **MySQL `jxj`** | 212 张业务表（**只读**，Mapper 分包隔离）+ 18 张 `ai_` 表 | 全部 |
| **Redis** | `ai:token:*` 登录令牌、`ai:sticky:*` 会话粘性（TTL 30 分钟） | 鉴权、路由 |
| **Elasticsearch** | `jxj_knowledge`：22 篇 / 233 个切片（IK 分词 + 1024 维向量） | 知识线 |
| **本地磁盘** | `data/knowledge-files/`：上传的原件（按内容指纹命名） | 答案溯源跳转 |

> ⚠️ ES 里还有个 `knowledge_base` 索引（42 篇）是**别的项目留下的，别动**。

## 六、名词对照

| 代码里的名字 | 中文 |
|---|---|
| `RoutingGraph` | 路由状态图（本项目骨架，11 个节点） |
| `CompositeGraph` | 跨域综合图 |
| `PublishGraph` | 发布图 |
| `dispatch` | 分派（唯一汇聚点） |
| `resolve` | 指代消解 |
| `classify` | 意图分类 |
| `synthesize` | 汇总（各域结果合成一条） |
| `interrupt` | 挂起（图停在那等人） |
| `checkpointer` | 检查点（把挂起状态存下来） |
| `state` / `node` / `edge` | 状态 / 节点 / 边 |
| 条件边 | conditional edge，按条件决定下一个节点 |
| reducer / 通道 | 多个节点写同一个字段时的合并规则 |
| 扇出 / 扇入 | fan-out / fan-in |
| `ReAct` | 推理 + 行动循环（模型想一步 → 调工具 → 看结果 → 再想） |
| `Agent` | 智能体：**模型决定下一步** |
| Workflow | 工作流：**代码决定下一步** |
| `BM25` / `KNN` | 关键词检索 / 语义（向量）检索 |
| `rerank` | 精排 |
| `RRF` | 倒数排名融合（把两路检索结果合成一份） |
| 证据闸 | 判断"资料够不够回答"的那道关 |

## 七、维护提示（改这份文档前先看）

**1. 主流程那两张图不是 Mermaid，是脚本生成的 SVG。**

因为 Mermaid 的自动布局在 27 个节点 / 39 条边上会把图拉成 **1515×3171 的一长条**，
塞进页面就成了一团糊（试过，确实糊）。所以主流程**坐标全部手控**：

```
docs/assets/gen-flow-svg.py     ← 改这个脚本，然后重跑
  ├─→ assets/flow-1-decision.svg    判定段（起点 → ①~⑧）
  └─→ assets/flow-2-execution.svg   执行段（⑧ → ⑨⑩⑪ → 汇聚）
```

```bash
python docs/assets/gen-flow-svg.py
```

**2. 其余几张小图仍然是 Mermaid**（整体分层 / 知识线对比 / 四张图关系 / 发布 / 数据存哪）——
它们节点少，Mermaid 渲染得挺好，而且改起来是改文本，比改脚本省事。

**3. 三个文件要同步。** `架构图.md`（给 IDE / GitHub）和 `架构图.html`（给浏览器双击看）
是同一套图，**以 `.md` 为准**——跟 `开发交接.md` → `交接摘要.md` 是同一个规矩。

**4. HTML 里的 Mermaid 有个坑：`<br/>` 必须转义成 `&lt;br/&gt;`。**

写在 `<pre class="mermaid">` 里的原始 `<br/>`，会被浏览器**当成真的换行元素解析掉**，
Mermaid 拿到的文本里换行就没了——节点标签挤成一长条
（`POST /api/chatPOST /api/chat/stream`），**不报错，只是难看**。
（.md 里不用转义，markdown 的代码围栏本来就是字面文本。）

**5. 图要跟代码一致。** 现在这份对的是：路由图 **11 节点 / 5 条件边**、
发布图 **4 节点 + 1 个挂起点**。代码改了先改图。

**6. 本地预览：**

```bash
python -m http.server 8899 --directory docs
# 然后打开 http://localhost:8899/架构图.html
```
