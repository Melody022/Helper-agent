## 一、主流程图：一条消息从进来到返回

> **读法**：①~⑦ 全是**判定**，所有判定最终都汇到 **⑧ 分派**；
> ⑧ 之后才分岔成四条执行路。**⑧ 是整个图唯一的汇聚点。**

```mermaid
flowchart TD
    START(["起点：用户发一句话"])

    START --> ID

    ID["① 身份检查<br/>查 MySQL 的 ai_user 表"]
    ID -->|"通过"| CMD
    ID -->|"拦下：未登录 / 账号不存在 / 账号停用"| D

    CMD["② 系统命令<br/>看是不是 /reset 这类指令"]
    CMD -->|"没命中"| SCAN
    CMD -->|"命中 /reset（顺带清 Redis 粘性）"| D

    SCAN["③ 开场扫描<br/>读粘性 + 关键词扫描 + 跨域判定<br/><b>三件事都是零成本，不叫模型</b>"]
    SCAN -->|"同时命中 ≥2 个业务域"| D
    SCAN -->|"关键词能定案"| KNOWN
    SCAN -->|"含「那台 / 它」+ 有上一轮"| D
    SCAN -->|"都不成立"| RESOLVE

    KNOWN["④ 关键词定案<br/>关键词判出的意图 vs 粘性里的意图<br/>一样沿用 / 不一样重新匹配"]
    KNOWN -->|"产出决策"| D

    RESOLVE["⑤ 指代消解<br/>用最近 5 轮把「那台」补成完整问题<br/>⚠️ 要叫一次本地小模型"]
    RESOLVE --> CLASSIFY

    CLASSIFY["⑥ 意图分类<br/>第1层 关键词加权 → 第2层 本地小模型 → 第3层 云端大模型"]
    CLASSIFY -->|"转人工 / 投诉"| D
    CLASSIFY -->|"模型判出多域"| D
    CLASSIFY -->|"正常"| MATCH

    MATCH["⑦ 匹配助手<br/>能力注册表 + 角色白名单 + 优先级<br/>匹配不到就用兜底助手（不挂任何工具）"]
    MATCH -->|"产出决策"| D

    D["⑧ 分 派 ◆<br/>① 先把「这句是啥意图、交给谁」推给前端<br/>② 再由条件边决定走哪条执行路<br/><b>⚠️ 审计在这之前已经落库</b>"]
    D -->|"短路：只回一句话"| E
    D -->|"知识类 → 问平台规则"| K1
    D -->|"跨域 → 一句话问了多个域"| C1
    D -->|"单域 → 正常查数据"| A1

    subgraph KG ["⑨ 知识线作答 — ⚠️ 不是 Agent，是代码写死的流水线"]
        direction TB
        K1["① 混合召回 20 条<br/>关键词 BM25 + 语义 KNN，RRF 融合"]
        K2["② 精排打分<br/>交叉编码器 gte-rerank-v2"]
        K3{"③ 证据闸<br/>分够不够回答？"}
        K4["回兜底话术<br/>+ 记进数据飞轮"]
        K5["④ 回填本体<br/>表格摘要 → 完整表格<br/>命中块 → 同章节邻块"]
        K6["⑤ 生成答案<br/>模型标 [1][2] 引用角标"]
        K7{"⑥ 自评<br/>本地小模型核对是否完全基于资料"}
        K8["出答案 + 溯源依据 sources"]

        K1 --> K2 --> K3
        K3 -->|"不够"| K4
        K3 -->|"够"| K5 --> K6 --> K7
        K7 -->|"不过"| K4
        K7 -->|"通过"| K8
    end

    subgraph CG2 ["⑩ 跨域作答 — ⚠️ 真并行，三个域同时跑"]
        direction TB
        C1["① 确定要跑哪几个域（最多 3 个）"]
        C2["② 三个域同时跑<br/>设备 / 租赁 / 知识"]
        C3["③ 汇总<br/>三份结果合成一条回答"]
        C1 --> C2 --> C3
    end

    subgraph AG ["⑪ 单域作答 — ⚠️ 这才是 Agent（ReAct 循环）"]
        direction TB
        A1["① 取工具白名单<br/>角色决定能看到哪些工具"]
        A2{"② 问模型<br/>还要调工具吗？"}
        A3["③ 执行工具<br/>查数据库"]
        A4["④ 出答案"]
        A1 --> A2
        A2 -->|"要调"| A3
        A3 -->|"结果丢回给模型"| A2
        A2 -->|"不用了"| A4
    end

    E(["⏹ 结束"])

    MERGE["汇聚：所有路径都回到这里<br/>存本轮用户消息 → 认不出意图就记飞轮 → 存助手回复 → 返回前端"]
    K4 --> MERGE
    K8 --> MERGE
    C3 --> MERGE
    A4 --> MERGE
    E --> MERGE
    MERGE --> FIN(["⏹ 结束"])

    style D fill:#ffe6cc,stroke:#d79b00,stroke-width:3px
    style KG fill:#d5e8d4,stroke:#82b366
    style CG2 fill:#dae8fc,stroke:#6c8ebf
    style AG fill:#e1d5e7,stroke:#9673a6
    style MERGE fill:#f5f5f5,stroke:#666
```

## 二、为什么知识线不做成 Agent

这是整个项目里最值得讲的一个设计判断。两张图对比：

```mermaid
flowchart LR
    subgraph BAD["如果知识线做成 ReAct Agent"]
        direction TB
        B1["模型拿到问题<br/>「押金怎么退」"] --> B2{"要不要调检索工具？"}
        B2 -->|"模型想：<br/>这个我训练数据里见过"| B3["不查资料<br/>直接凭印象答"]
        B2 -->|"决定查"| B4["检索 → 精排 → 证据闸"]
        B3 --> B5["❌ 编出一条平台规则<br/>用户拿到自信满满但错误的答案"]
        B4 --> B6["✅ 正确答案"]
    end

    subgraph GOOD["实际：知识线是代码写死的流水线"]
        direction TB
        G1["用户问题"] --> G2["代码强制：先召回"]
        G2 --> G3["再精排"]
        G3 --> G4["再过证据闸"]
        G4 -->|"资料不够"| G5["✅ 直接回兜底话术<br/>模型压根没机会开口"]
        G4 -->|"资料够"| G6["✅ 生成答案"]
    end

    style BAD fill:#f8cecc,stroke:#b85450
    style GOOD fill:#d5e8d4,stroke:#82b366
```

**判据不是"这条线上有没有调模型"，而是"下一步由谁决定"。**

| | 知识线（工作流） | 如果做成 ReAct Agent |
|---|---|---|
| 能跳过检索吗 | 不能，顺序写死 | **能** |
| 能绕过证据闸吗 | 不能，闸在生成**之前** | **能** |
| 会编平台规则吗 | 不会 | **可能** |

## 三、四张图怎么串起来的

```mermaid
flowchart TD
    HTTP["HTTP 请求"] --> CS["对话服务 ChatService"]
    CS --> RG["<b>路由状态图 RoutingGraph</b><br/>11 节点 / 5 条件边"]

    RG -->|"知识类"| KL["知识线<br/>（不是图，是一条 Java 链）"]
    RG -->|"跨域"| CG["跨域综合图 CompositeGraph<br/>并行扇出 + 汇总"]
    RG -->|"单域"| RA["ReAct 助手 ×4<br/>库预置 ReactAgent"]

    CG -->|"每个域节点内部调用"| RA

    PG["发布图 PublishGraph<br/>4 节点 + interrupt 挂起点<br/>+ MySQL 检查点"]
    PA["发布助手 PublishAgent"] -.->|"独立一条线<br/>不在上面任何图里"| PG

    style RG fill:#ffe6cc,stroke:#d79b00,stroke-width:2px
    style PG fill:#fff2cc,stroke:#d6b656
```

**"谁决定走向"总结**（这是项目的设计主线）：

| 图 | 谁决定下一步 | 用到的 LangGraph 能力 |
|---|---|---|
| `RoutingGraph` | **代码** | 条件边 ×5、dispatch 汇聚、`recursionLimit(20)` |
| `CompositeGraph` | **代码**（决定扇出） | 隐式并行节点、appender 通道、扇入 |
| `ReactAgent` ×4 | **模型** | 库预置 ReAct 循环、工具调用 |
| `PublishGraph` | **代码** | **interrupt 挂起 + checkpointer** |

## 四、发布：另一条独立的线（human-in-the-loop）

```mermaid
flowchart TD
    U(["用户：帮我发布一台出租"]) --> H

    H["handle<br/>抽字段 + 校验"]
    H -->|"字段没齐"| ASK["追问缺什么<br/>（模型只负责抽字段）"]
    ASK --> E1(["⏹ 结束（这一轮到此为止）"])

    H -->|"字段齐了"| SUM["给确认摘要 + 一次性验证码"]
    SUM --> INT{{"☆ interrupt 挂起 ☆<br/>图停在这里等人<br/>状态写进 ai_graph_checkpoint<br/>⚠️ 进程重启也不丢"}}

    INT -->|"用户下一轮回复"| BR{"用户说了什么？"}
    BR -->|"取消"| CN["作废草稿"]
    BR -->|"补充 / 修改"| H
    BR -->|"确认发布"| W["校验验证码<br/>（有效期 + 是否用过）"]
    W -->|"验证码不对"| WARN["提示核对"]
    W -->|"通过"| WRITE["落库，进入待审核"]
    CN --> E2(["⏹ 结束"])
    WARN --> E2
    WRITE --> E2

    style INT fill:#fff2cc,stroke:#d6b656,stroke-width:3px
```

**为什么这里必须用 checkpointer**：图挂起后，下一轮请求得**从挂起点恢复**——
"挂在哪"必须有地方存。库里只自带 `MemorySaver`（重启就没，和项目原则冲突）
和 `FileSystemSaver`（写本地磁盘），所以自己实现了一个 `MysqlCheckpointSaver`。

## 五、数据存在哪

```mermaid
flowchart LR
    subgraph W["一轮对话会写这些"]
        direction TB
        W1["审计一条 → ai_audit_log<br/>（在 ⑧ 之前就写了）"]
        W2["会话粘性 → Redis ai:sticky:*<br/>（命中助手时）"]
        W3["用户消息 + 助手回复 → ai_message<br/>（在图之后写）"]
        W4["图检查点 → ai_graph_checkpoint<br/>（只有发布图挂起时）"]
        W5["飞轮候选 → ai_flywheel_candidate<br/>（意图认不出 / 知识线拒答时）"]
    end
```

| 存储 | 存什么 | 谁在用 |
|---|---|---|
| **MySQL `jxj`** | 212 张业务表（**只读**，Mapper 分包隔离）+ 18 张 `ai_` 表 | 全部 |
| **Redis** | `ai:token:*` 登录令牌、`ai:sticky:*` 会话粘性（TTL 30 分钟） | 鉴权、路由 |
| **Elasticsearch** | `jxj_knowledge`：22 篇 / 233 个切片（IK 分词 + 1024 维向量） | 知识线 |
| **本地磁盘** | `data/knowledge-files/`：上传的原件（按内容指纹命名） | 答案溯源跳转 |

> ⚠️ ES 里还有个 `knowledge_base` 索引（42 篇）是**别的项目留下的，别动**。

## 六、名词对照
| 代码里的名字 | 中文 |
|---|---|
| `RoutingGraph` | 路由状态图（本项目骨架，11 个节点） |
| `CompositeGraph` | 跨域综合图 |
| `PublishGraph` | 发布图 |
| `dispatch` | 分派（唯一汇聚点） |
| `resolve` | 指代消解 |
| `classify` | 意图分类 |
| `synthesize` | 汇总（各域结果合成一条） |
| `interrupt` | 挂起（图停在那等人） |
| `checkpointer` | 检查点（把挂起状态存下来） |
| `state` / `node` / `edge` | 状态 / 节点 / 边 |
| 条件边 | conditional edge，按条件决定下一个节点 |

## 七、维护提示（改这份文档前先看）

**1. 两个文件要同步。** `架构图.md`（给 IDE / GitHub 渲染）和 `架构图.html`（给浏览器双击看）
是同一套图。**以 `.md` 为准**，改完记得同步 `.html`——跟 `开发交接.md` → `交接摘要.md`
是同一个规矩（派生品不作为独立真相来源）。

**2. HTML 里的 `<br/>` 必须转义成 `&lt;br/&gt;`。** 这是唯一一个会静默出错的地方：

- 写在 `<pre class="mermaid">` 里的原始 `<br/>`，会被浏览器**当成真的换行元素解析掉**，
  Mermaid 拿到的文本里换行就没了 —— 节点标签会挤成一长条（`POST /api/chatPOST /api/chat/stream`），
  **不报错，只是难看**
- 转义成 `&lt;br/&gt;` 之后，浏览器把它还原成字面文本 `<br/>`，Mermaid 才认得出这是换行

`.md` 里**不需要转义**（markdown 的代码围栏本来就是字面文本）。

**3. 图要跟代码一致。** 现在这份对的是：路由图 **11 节点 / 5 条件边**、
发布图 **4 节点 + 1 个挂起点**。代码改了先改图。

**4. 预览命令**（项目里已配好 `.claude/launch.json`）：

```bash
python -m http.server 8899 --directory docs
# 然后打开 http://localhost:8899/架构图.html
```
