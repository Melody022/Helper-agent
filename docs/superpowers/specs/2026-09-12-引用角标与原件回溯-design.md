> 相关：`docs/开发交接.md`、`docs/RAG迭代与优化-面试用.md`、`docs/踩坑记录与量化数据.md`

## 一、为什么做这件事

上一轮（`20ad5f4`）把**结构元数据**补上了：切片带 `section_path` + `page_no`，
聊天响应里也带了 `sources`（标题 / 章节路径 / 页码 / 原文片段），聊天页能展开看依据。

但这条溯源链**断了最后一截**：

| 已经有了 | 还缺的 |
|---|---|
| 切片带 `docId` + `pageNo` | **原件根本没存**——上传时 `file.getBytes()` 读进内存、解析完就丢 |
| 资料在提示词里已编号（`<1><2>…`），顺序与 `sources` 一致 | **答案正文里没有角标**——没法把"这一句"对回"那一条" |
| 响应里有 `sources` | **`Source` 里没有 `docId`**——前端不知道该打开哪份文件 |
| 管理台能看知识库列表 | **没有查看器**——点开也看不到原件 |

结果就是：用户看到"依据来自《矿用机械正铲式挖掘机 安全要求》第 10 页"，
**却没法跳到那一页去看**。溯源停在"文字片段"，建立信任的效果打了对折。

**本轮的完成定义**：答案正文里的 `[1]` 可点 → 点开看到**原始 PDF 的第 10 页**。

---

## 二、范围

### 本轮做

1. 上传时保留原件（落盘），`ai_knowledge_doc` 加文件字段
2. **Office 文档**在上传时转一份 PDF 预览件（best-effort）；其余格式一律原样返回原件
3. 两个文件接口：聊天页预览（登录即可）、管理台下载（ADMIN）
4. 提示词让模型标 `[序号]` + 服务端净化编号
5. 聊天页角标渲染 + PDF.js 内嵌查看器

### 本轮**不做**（照实记，别假装做了）

| 不做的事 | 为什么 | 什么时候做 |
|---|---|---|
| **NLI 逐句校验** | 是独立的一轮：每次要多一轮模型调用、阈值要单独校准、会改变"答不答"的行为 | 下一轮 |
| **高亮命中的原句** | 那份国标是**全扫描件、没有文字层**，PDF.js 也高亮不了；对带文字层的 PDF 才有效 | 待定 |
| 原件存对象存储（OSS） | 本地演示，落盘足够；换 OSS 只需换一个 `FileStore` 实现 | 上线前 |
| 版式还原 / 章节树导航 | 和"跳回原件"无关 | 见交接文档待办 |

### 一条必须写明的边界

**本轮只保证角标的"编号合法"，不保证"标得对"。**
模型完全可能把其实是 `[1]` 的内容标成 `[3]`——净化只能拦住越界的编号，
拦不住"标错位置"。**这正是下一轮 NLI 逐句校验要解决的问题**，
面试被问到时要主动说清楚这个边界。

## 三、数据层

### 配置

```yaml
rag:
  upload:
    dir: data/knowledge-files    # 原件与预览件落盘目录（相对工作目录）
```

- 加进 `.gitignore`（原件的体积不可控，不该进仓库）
- 启动时确保目录存在

### 表结构（V4 迁移，照 V2/V3 的幂等写法）

`ai_knowledge_doc` 加 4 列：

| 列 | 类型 | 说明 |
|---|---|---|
| `file_name` | varchar(255) | 原始文件名，如 `GBT+25523-2022.pdf` |
| `file_path` | varchar(500) | 原件落盘的相对路径 |
| `preview_path` | varchar(500) | 预览件（PDF）相对路径，可空 |
| `file_size` | bigint | 原件字节数 |

### 落盘命名

用**现成的** `sourceId`（内容指纹 `upload-<sha256前16位>`）当文件名：

```
data/knowledge-files/upload-a1b2c3d4e5f6a7b8.pdf         ← 原件
data/knowledge-files/upload-a1b2c3d4e5f6a7b8.preview.pdf ← 转出的预览件
```

**为什么用 `sourceId`**：它已经是入库查重的键（同一份文件重复上传会被跳过），
用它当文件名就**天然去重**——不会因为反复上传堆出一堆同样的文件。
两份不同内容但同名的文件也不会互相覆盖。

## 四、上传链路

改 `AdminKnowledgeController.upload`：

```
① 读 bytes
② 落盘原件                                    ← 新增
③ 解析（现状不变）
④ 入库（现状不变）
⑤ **仅当原件是 Office**：转一份 PDF 预览件（best-effort，失败只记 warning）  ← 新增
⑥ 把 file_name/file_path/preview_path/file_size 写回文档记录
```

### 各类型怎么处理：**默认返回原件，只有渲染不了的才转**

**原则：转 PDF 不是默认动作，是例外。** 知识库存的是什么，就尽量返回什么。

| 原件类型 | 预览返回什么 | 为什么 |
|---|---|---|
| **PDF** | **原件** | PDF.js 直接渲染 |
| **图片**（png/jpg/gif/webp/bmp） | **原件** | 浏览器 `<img>` 直接显示，不转 |
| **txt / csv / md** | **原件**（`text/plain`） | 浏览器本来就能显示纯文本，前端自己排版（等宽 + 保留换行） |
| **Word / Excel / PPT** | **转出的 PDF 预览件** | ⚠️ **唯一需要转的一类**：浏览器没有能力渲染 docx/xlsx/pptx，只会触发下载——而那和"聊天页只预览"冲突 |
| 其它（zip 等） | 不给预览 | `previewable = false`，角标降级成只展开文字片段 |

`preview_path` 这个字段的语义因此收窄为：**「仅 Office 文档需要的 PDF 预览件」**，
其余类型一律为 null（原件自己就能预览）。

### 两条硬约束

1. **转预览件是 best-effort，绝不能影响入库。** 转失败只记 warning、`preview_path` 留空。
   项目里已经吃过一次亏：非致命步骤把主流程拖垮（踩坑第 35 条，Office 文档被误判"需要 OCR"
   之后整篇解析失败）。**预览是锦上添花，入库是本职。**
2. **任何一步失败都要留下可诊断的痕迹**（踩坑第 36 条：失败后停在半成品状态最难受）。
   落盘失败要让上传明确失败并说明原因；转预览失败要写进日志 + 一个前端可见的 warning。

## 五、接口层

鉴权现状：`WebConfig` 对 `/api/**` 全量挂 `AuthInterceptor`（登录校验），
`@RequireRole(ROLE_ADMIN)` 再加一道角色。新增接口挂进这套即可。

| 接口 | 权限 | 响应 |
|---|---|---|
| `GET /api/knowledge/files/{docId}/preview` | 登录即可 | **按原件类型给 Content-Type**：`application/pdf` / `image/png` / `text/plain`…；Office 文档给转出的 PDF。一律 `Content-Disposition: inline` |
| `GET /api/admin/knowledge/{docId}/file` | `@RequireRole(ADMIN)` | **原件**，`Content-Disposition: attachment`（原名下载） |

**注意两个接口返回的可能不是同一个文件**：预览接口对 Office 文档给的是**转出来的 PDF**，
而下载接口给的是**原始 docx**。这是有意的——运营要的是能归档的原件，
用户要的是能看的页面。

### ⚠️ 一个必须处理的细节：`<iframe src>` 带不了 `Authorization` 头

前端**不能**把接口 URL 直接塞进 `<iframe src>`——那样请求不带令牌，会被拦截器 401 掉。
正确做法：

```
fetch(url, { headers: { Authorization: 'Bearer ' + token } })
  → response.blob()
  → URL.createObjectURL(blob)
  → 喂给 PDF.js（拿 ArrayBuffer）或 <img>（拿 blob URL）
```

**这反倒和"聊天页只预览、不给下载"是一致的**：不暴露一个能直接访问的 URL，
用户拿不到一个可以另存/转发的链接。用完记得 `URL.revokeObjectURL()`。

### DTO 变更

`KnowledgeAnswerService.Source` 加两个字段：

```java
public record Source(Long docId, String title, String sectionPath, Integer pageNo,
                     String snippet, boolean previewable) { }
```

- `docId`：前端据此决定打开**哪份**文件（现在没有这个字段，前端根本定位不到）
- `previewable`：这份原件有没有浏览器能直接看的形式（PDF / 图片 / 纯文本都算，
  Office 看转换是否成功，zip 之类不算）。**提前告诉前端**，
  免得点开一个角标才发现"这份没有预览"，还要等一次失败的请求

**不复用 `preview_path` 直接暴露给前端**：那是服务端文件路径，
对客户端没有用处，只有信息泄露的份。布尔值足够表达前端需要知道的事。

`ChatResponse` 是 record，跟着走。

## 六、角标：提示词 + 服务端净化

### 提示词

`knowledge-generation.md` 加一条规则：

> 每句结论后用 `[序号]` 标注依据来自第几条资料。序号就是资料前的 `<1><2>` 编号。
> 资料里没有依据的结论，不要标序号，也不要写出来。

### 服务端净化（重点）

**只靠提示词一定会出问题**，而且错法可预测：

| 模型可能的输出 | 处理 |
|---|---|
| `[7]` 但只有 5 条依据 | **降级成纯文本**，不做成可点链接 |
| `【1】` / `［1］`（全角） | 归一化成 `[1]` |
| `[0]` / `[-1]` | 同越界，降级 |
| 句子中间夹 `[1]` | 正常处理 |

新增纯函数 `CitationSanitizer`：

```java
/**
 * 归一化答案正文里的引用写法，让前端只需要认一种形态。
 * 只做"改写"，不做"删改内容"——越界编号原样留着，由渲染层决定不链接。
 */
static String normalize(String answer)   // 【1】/［1］ → [1]；其余原样

/** 编号是否指向一条真实存在的依据。前端据此决定"做成可点角标"还是"留成纯文本"。 */
static boolean isValid(int index, int sourceCount)   // 1 <= index <= sourceCount
```

- **越界编号降级成纯文本**：宁可少一个角标，也不能让用户点开一个**错的原件**——
  那比没有链接更伤信任
- 抽成**纯函数 + 单测**。理由和踩坑第 32 条一样：这类"模型输出格式"的问题
  在真实对话上很难稳定复现，必须能单测

### 职责边界：**不跨层传 HTML**

| 层 | 负责 | 不负责 |
|---|---|---|
| 后端 `CitationSanitizer` | 把 `【1】` 归一成 `[1]`；提供"编号是否合法"的判据 | **不拼 HTML、不动正文内容** |
| 前端 | **转义**正文，再把合法编号替换成 `<sup class="cite">` | 不判断"哪些编号合法"的规则（只调后端给的判据） |

**为什么不许后端返回 HTML**：那样前端必须"信任这段 HTML 不转义"，
而这段文本里混着**用户上传的文档内容**——一旦哪天后端漏转义一处就是一个 XSS。
**HTML 只在渲染层生成，转义也只在渲染层做**，一个地方、一个顺序，不给自己留犯错的机会。

## 七、前端

### 角标渲染

聊天页现在是 `b.textContent = text`。改成：

```js
// ⚠️ 顺序不能反：先转义再替换。
// 知识库内容是**用户上传的文档**，里面完全可能有尖括号或 <script>。
b.innerHTML = renderCitations(esc(text), sources);
//                            ↑ 转义   ↑ 只替换 1..sources.length 范围内的编号
```

`renderCitations` 只把**合法编号**替换成：

```html
<sup class="cite" data-i="1">[1]</sup>
```

### 点击行为

点角标 → 弹层：

```
┌────────────────────────────────────────────┐
│ [1] 矿用机械正铲式挖掘机 安全要求            │  ← 依据卡片
│ 5 安全要求 > 5.4 润滑系统 · 第 11 页         │
│ "……润滑系统应安全可靠，防止……"              │
├────────────────────────────────────────────┤
│                                            │
│            PDF.js 单页 canvas              │  ← 直接定位到第 11 页
│                                            │
├────────────────────────────────────────────┤
│  ‹ 上一页   第 11 页 / 共 15 页   下一页 ›    │
│                          [在管理台打开原件] │  ← 仅 ADMIN 登录时显示
└────────────────────────────────────────────┘
```

- **没有下载按钮**（聊天页只预览——这是明确的产品决策，不是漏做）
- 依据卡片上如果只有标题、没有章节内容，就展示 `sources` 里的 `snippet`
- `pageNo` 为空（FAQ 类语料没有"页"的概念）→ 打开第 1 页并明说"这条没带页码"
- **按预览件的类型切换主体**（这就是"知识库是什么就返回什么"在前端的落地）：

  | 预览件 Content-Type | 主体 |
  |---|---|
  | `application/pdf` | PDF.js 单页 canvas + 翻页（原件是 PDF，或原件是 Office 转出来的） |
  | `image/*` | `<img>`（可点开放大），没有翻页 |
  | `text/plain` | `<pre class="raw">` 等宽显示，没有翻页 |
  | 拿不到（`previewable = false`） | 只显示依据卡片，并说明"这份原件格式不支持预览" |

- "在管理台打开原件"只在当前账号是 ADMIN 时出现

### 静态资源

`pdf.js` vendor 到 `src/main/resources/static/vendor/pdfjs/`（**进 git**）。
两个页面现在都是一行外链都没有的自包含风格，vendor 之后保持一致、离线可用。

## 八、测试

| 测什么 | 怎么测 | 为什么值得测 |
|---|---|---|
| `CitationSanitizer` | 纯函数单测：越界、全角写法、`[0]`/负数、连续多个角标、正常路径、角标前后有文字 | 模型输出格式问题无法在真实对话上稳定复现 |
| 上传落盘 | 落盘路径、文件名用 `sourceId`、**传两次只有一个文件**（去重） | 去重是这套命名方案的唯一理由，必须锁住 |
| 预览返回什么 | **PDF / 图片 / txt / csv / md 一律原样返回原件**（Content-Type 正确）；**只有 Office 才走转换**；**Office 转失败不影响入库** | 前两条锁住"默认返回原件"这个原则不被改回去；第三条防 best-effort 退化成 must-succeed |
| 接口权限 | 未登录 401；普通用户能拿 preview；普通用户拿不到 admin 下载 | 权限回归 |
| `Source` 带 `docId` | 传递链路 | 前端定位文件的唯一依据 |
| **角标生成本身** | **不断言** | 照 `M6KnowledgeTest` 的经验：不要把测试建立在模型的自由输出上 |

## 十、风险与已知取舍

| 风险 | 处置 |
|---|---|
| 上传耗时增加（转 PDF） | 可接受：上传本来就慢（扫描件 83 秒），预览是用户盯着看的动作 |
| LibreOffice 不在 PATH 时转不了 | 已有前例（踩坑记录里的 PATH 坑）。**只影响 Office 文档的预览**，不影响入库也不影响其它格式的预览，且要有明确日志 |
| 原件占磁盘 | 本地演示可接受。落盘目录可配置；换 OSS 只需替换 `FileStore` 实现 |
| 模型不标角标 | 提示词是**尽力而为**。模型完全不标时，答案照常返回，只是没有角标——不阻塞主流程 |
| 用户上传的文档含恶意 HTML | **先转义再替换**；PDF 走 PDF.js 渲染在 canvas 上，不解析 HTML |
